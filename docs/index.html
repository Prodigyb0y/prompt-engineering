1.Resumo executivo

Equipes de negócio recebem solicitações em texto livre que precisam virar dados estruturados. A forma de pedir ao modelo (o prompt) afeta o acerto, o custo e o tempo de resposta. Este estudo mede essas três coisas na mesma tarefa.

2.Metodologia

Tarefa e dados

Dado um pedido de compra escrito como num e-mail, o modelo devolve um JSON com 8 campos: solicitante_area, item, quantidade, unidade (un, kg, m, l ou cx), prazo_entrega (AAAA-MM-DD ou null), valor_unitario, moeda (BRL, USD, EUR ou null) e fornecedor. Os 50 textos são sintéticos, gerados por script (seed 42), cada um com o gabarito escrito e congelado (hash registrado) antes da primeira execução. Cada caso pertence a um tipo (por exemplo, valor em formato brasileiro, prazo relativo, informação ausente).

3.Resultados

Resultado oficial da rodada selecionada. Todas as técnicas receberam os mesmos casos.

Acerto por caso

Maior é melhor. A barra preta é o intervalo de confiança de 95%. Uma técnica só é declarada melhor que outra se os intervalos não se sobrepõem e o teste do sinal exato pareado dá p < 0,05 (tabela abaixo).

Comparações pareadas entre técnicas

Teste do sinal exato, bilateral, por caso (cada caso conta uma vez, com o acerto médio das repetições; empates saem do teste). Com poucos casos discordantes, mesmo 4 a 0 não chega a p < 0,05.

Acerto por tipo de caso

Cada célula mostra o acerto e o número de respostas certas. Há poucos casos por tipo (número entre parênteses), então estes valores indicam onde olhar, não bastam como prova. Selecionar uma célula abre o tipo no explorador.
